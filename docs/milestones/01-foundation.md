# 第一阶段：工程基础

## 目标与范围

建立 Go 模块、Gin 服务、本地 MySQL 8.4 环境和工程文档。交付范围限于运行环境、数据库连接初始化与健康检查。座位、订单、支付、候补和后台任务留待后续阶段。

## 技术设计、数据模型与接口

- 采用模块化单体。服务默认在 `127.0.0.1:8080` 监听，可通过 `HTTP_ADDR` 调整。
- 设置 `MYSQL_DSN` 时，服务启动前通过 GORM 初始化 MySQL 连接。
- `GET /healthz` 返回 HTTP 200 和 `{"status":"ok"}`，表示 HTTP 服务可响应。
- 票务表结构和迁移脚本将在后续阶段引入。MySQL 数据卷支持跨容器重启持久化。

## 正确性约束

- 票务一致性约束记录在[总体架构](../architecture.md)，并在实现对应业务时通过真实 MySQL 测试验证。
- 本地密码从环境配置提供，环境变量样例只保留空的密码字段。

## 实现与验收

| 验收项 | 验证方式 |
| --- | --- |
| Go 模块和依赖完整 | `go mod tidy` 退出码为 0 |
| Go 工程可编译并通过静态检查 | 执行 `go test ./...` 和 `go vet ./...` |
| 本地数据库可运行 | 按[启动说明](../../README.md)执行 Compose 启动命令，确认 MySQL 进入健康状态 |
| HTTP 服务可运行 | 启动服务并请求 `/healthz`，确认状态码和 JSON 响应 |
| 可选数据库连接可用 | 配置有效的 `MYSQL_DSN` 启动服务，确认启动成功 |

## 已知限制

完整数据库验收依赖 Docker 与 Compose V2。健康检查接口只反映 HTTP 进程的状态，数据库健康状态通过 Compose 单独查看。
